# 水利具身智能协同指挥中心：正式系统全流程操作手册

适用对象：系统管理员、值守人员、设备工程师和现场安全负责人。

本文覆盖从首次部署、系统激活、设备连接、数据验收，到日常值守、异常处理和后续真实控制接入的完整流程。

> **当前系统边界**：正式入口用于接收真实遥测、传感器、告警、电子围栏和任务申请。浏览器不会直接控制无人机、无人船、轮式机器人或机器狗。真实控制必须由另行部署并通过安全评审的现场边缘执行适配器完成。

---

## 1. 系统组成与访问地址

```text
无人机 / 无人船 / 轮式机器人 / 机器狗
                 │
                 ▼
        现场边缘适配器（厂商协议转换）
                 │
                 ▼
    正式系统网关 127.0.0.1:8878
                 │
                 ▼
    正式运营页面 http://127.0.0.1:8080
                 │
                 ▼
  态势总览 / 事件管理 / 协同编排 / 围栏 / 传感监测
```

| 地址或文件 | 用途 | 谁使用 |
|---|---|---|
| `http://127.0.0.1:8080` | 正式运营页面 | 值守人员、管理员 |
| `http://127.0.0.1:8878` | 本机实时网关 | 边缘适配器，不直接给浏览器使用 |
| `启动正式系统.cmd` | 日常一键启动 | 值守人员 |
| `首次部署正式系统.cmd` | 首次安装、构建并启动 | 系统管理员 |
| `data/operator-state.json` | 本机围栏运行状态 | 系统自动维护；不要手工修改 |

正式网关默认仅监听本机。第一阶段应把正式系统和边缘适配器部署在同一台现场工控机上，适配器通过 `127.0.0.1:8878` 写入数据。

## 3. 首次激活正式系统

这里的“激活”指完成本机正式运行环境的安装和启动，不包含任何授权码或云端账户操作。

### 3.1 首次部署

1. 确认电脑已安装 Node.js 和 Microsoft Edge，且项目位于：

```text
E:\Codex\water-embodied-command-center
```

2. 双击项目根目录中的：

```text
首次部署正式系统.cmd
```

3. 首次脚本会自动完成依赖安装、正式前端构建并打开浏览器。
4. 浏览器打开后，确认地址为：

```text
http://127.0.0.1:8080
```

5. 页面右上角应显示“集成网关”。首次没有连接设备时，页面显示“等待现场设备接入”“暂无现场告警”是正确状态，不是故障。

### 3.2 激活检查

若需要核对状态，在 PowerShell 中运行：

```powershell
Invoke-RestMethod http://127.0.0.1:8080/health
```

预期结果示例：

```json
{
  "status": "ok",
  "mode": "integration",
  "deviceCount": 0,
  "alertCount": 0,
  "liveCommandAvailable": false
}
```

其中：

- `status: ok`：系统已启动。
- `mode: integration`：正式现场集成模式。
- `deviceCount: 0`：尚未接入设备时正常。
- `liveCommandAvailable: false`：安全机制正常，网页不能直接控制真实设备。

### 3.3 日常启动

从第二次开始，只需双击：

```text
启动正式系统.cmd
```

不要把开发演练地址 `http://127.0.0.1:5173` 当作日常值守入口；正式值守使用 `8080`。

## 4. 接入前登记设备

在连接设备前，管理员与设备工程师先完成下表。每个设备 ID 必须唯一且长期固定。

| 类别 | 示例设备 ID | 上游连接方式 | 必须确认的数据 |
|---|---|---|---|
| 无人机 | `UAV-D01` | MAVLink 2 / 厂商 SDK | 心跳、位置、电量、速度、飞行高度、云台温度 |
| 无人船 | `USV-B01` | MQTT 5 / 厂商 SDK | 船况、位置、电量、pH、浊度、水温 |
| 轮式机器人 | `UGV-R01` | ROS 2 / 厂商 SDK | 位姿、电量、柜体温度、振动、气体、急停状态 |
| 机器狗 | `QGV-Q01` | ROS 2 / 厂商 SDK | 位姿、电量、坡度、表面温度、气体、急停状态 |

还必须登记：设备型号、序列号、所属工程区、联系人、通信链路、协议版本、坐标系、低电量阈值、失联策略、急停位置和人工接管方式。

不要在此系统、文档或聊天中保存证书私钥、密码、Token、SIM 卡凭据或公网 IP。

## 5. 连接设备：安装并运行边缘适配器

### 5.1 为什么需要边缘适配器

正式系统不直接连接飞控、电机、ROS 2 控制话题或 MQTT 控制主题。边缘适配器负责把设备厂商协议转换为平台统一遥测，并在本地执行安全检查。

```text
设备原始数据 → 边缘适配器校验/转换 → 平台网关 → 正式页面
```

适配器应运行在同一台现场工控机，或运行在经过专网和认证保护的设备侧工控机。当前第一阶段只实施“只读上报”，不实施真实设备控制。

### 5.2 无人机连接

1. 将飞控或厂商地面站连接至现场工控机。
2. 在边缘适配器中配置 MAVLink 2 或厂商 SDK 的只读遥测连接。
3. 读取心跳、电池、位置、速度、飞行状态和云台诊断。
4. 将高度、风速和云台温度写入统一 `sensors` 字段。
5. 每 1–2 秒向网关上报一次。

无人机适配器应至少能上报：

```json
{
  "deviceId": "UAV-D01",
  "type": "drone",
  "state": "在线巡检",
  "battery": 78.4,
  "linkQuality": 96,
  "speed": 12.6,
  "location": "主坝东侧",
  "x": "72%",
  "y": "42%",
  "protocol": "mavlink",
  "sensors": {
    "flightAltitude": 121.6,
    "windSpeed": 5.3,
    "cameraTemp": 38.1
  }
}
```

### 5.3 无人船连接

1. 在船坞或水面通信工控机连接厂商 Broker 或 MQTT 5 Broker。
2. 每艘船使用独立身份和 ACL，订阅船况、水质、测深、GNSS 和电池主题。
3. 在适配器中校验消息时间、QoS、序号和设备身份。
4. 将 pH、浊度和水温写入：

```json
"sensors": {
  "ph": 7.2,
  "turbidity": 18.6,
  "waterTemp": 24.2
}
```

5. 失联、定位无效或水质超阈值时，由适配器立即上报告警。

### 5.4 轮式机器人连接

1. 在泵站、闸站或厂区工控机部署 ROS 2/厂商 SDK 适配器。
2. 订阅位姿、电池、设备诊断、柜体温度、振动、气体和急停健康状态。
3. 标准化为：

```json
"sensors": {
  "cabinetTemp": 32.4,
  "vibration": 1.6,
  "gas": 2
}
```

4. 首先在静止状态验证遥测；再验证失联、低电量、急停和传感器异常上报。

### 5.5 机器狗连接

1. 在堤坝或地下廊道的就地工控机运行 ROS 2/厂商 SDK 适配器。
2. 读取位姿、足端状态、电量、坡度、表面温度、气体和急停状态。
3. 标准化为：

```json
"sensors": {
  "slopeAngle": 18.2,
  "surfaceTemp": 29.2,
  "gas": 2
}
```

4. 先完成静态、牵引保护、遥控接管和急停测试，才可进行低速巡检。

## 6. 将适配器数据写入正式网关

适配器向本机发送统一 HTTP 请求：

```text
POST http://127.0.0.1:8878/api/v1/ingest/telemetry
Content-Type: application/json
```

同一台工控机上可先使用下面的 PowerShell 报文验证链路。它只验证数据接入，不会控制任何设备：

```powershell
$body = @{
  deviceId = 'UAV-D01'
  type = 'drone'
  label = '无人机 D-01'
  state = '在线巡检'
  battery = 73.5
  linkQuality = 96
  speed = 12.8
  location = '主坝东侧'
  x = '72%'
  y = '42%'
  protocol = 'mavlink'
  sensors = @{
    flightAltitude = 121.6
    windSpeed = 6.2
    cameraTemp = 38.1
  }
} | ConvertTo-Json -Depth 3

Invoke-RestMethod -Method Post -Uri 'http://127.0.0.1:8878/api/v1/ingest/telemetry' -ContentType 'application/json' -Body $body
```

返回 `accepted: true` 后，刷新 `http://127.0.0.1:8080`。系统应出现 `UAV-D01`，并可在三维地图和“传感监测”面板中查看数据。

告警使用：

```text
POST http://127.0.0.1:8878/api/v1/ingest/alerts
```

```json
{
  "level": "critical",
  "title": "UAV-D01 链路质量异常",
  "place": "主坝东侧",
  "confidence": "95%",
  "source": "uav-edge-adapter"
}
```

适配器程序代替 PowerShell 后，必须持续上报；网页不会自行编造设备状态。

## 7. 设备接入验收

每接入一类设备，都按以下顺序验收：

1. **网关检查**：`http://127.0.0.1:8080/health` 返回 `status: ok`。
2. **在线检查**：设备卡片在正式页面出现，ID、类别和位置正确。
3. **遥测检查**：电量、链路、速度与至少三项传感器在 5 秒内刷新。
4. **地图检查**：用现场地标校准 `x/y` 映射，确认设备显示在正确区域。
5. **告警检查**：制造一个可控的低风险测试条件，确认告警出现、可确认、可追溯。
6. **围栏检查**：网页建立测试围栏，设备侧安全控制器配置同一审批版本；接近边界时必须由设备侧拒绝危险动作。
7. **安全检查**：验证急停、人工接管、失联和低电量策略。此项必须由现场安全负责人签字。

只有上一项通过，才进入下一项；先单设备，再多设备。

## 8. 日常值守使用流程

### 8.1 班前启动

1. 双击 `启动正式系统.cmd`。
2. 打开 `http://127.0.0.1:8080`，确认“集成网关”。
3. 查看设备数量、未确认告警和链路质量。
4. 打开“传感监测”，核对各设备是否有最新传感器读数。
5. 打开“电子围栏”，确认当天有效的禁入区、限高区和水面作业区。
6. 确认现场遥控器、急停、人工接管和应急联系人可用。

### 8.2 运行中操作

| 场景 | 值守人员操作 | 系统实际行为 |
|---|---|---|
| 查看设备 | 在左侧设备列表或三维地图选择设备 | 显示网关最新状态和传感器 |
| 查看环境 | 打开“传感监测” | 按设备类别展示三项标准化测点 |
| 创建作业边界 | 打开“电子围栏”，地图点选至少 3 点并保存 | 网关保存围栏；需另行同步至设备安全控制器 |
| 处理告警 | 点击告警，核对证据和位置，人工确认 | 生成处置记录，不等同于设备动作 |
| 提交协同任务 | 在事件管理或协同编排中提交 | 状态为待现场审批，设备不会直接执行 |
| 查看视频 | 打开“实时画面” | 仅显示已接入且经鉴权的视频网关流 |

### 8.3 班后检查

1. 确认所有告警已记录、确认或移交。
2. 导出或备份适配器日志、遥测日志和审批记录。
3. 核对围栏版本与设备安全控制器版本一致。
4. 确认设备已按现场规程停靠、充电或交接。
5. 仅在值守结束后由管理员按现场运维规程停止工控机服务。

## 9. 异常处理

| 现象 | 首先检查 | 处理方式 |
|---|---|---|
| `8080` 无法打开 | 是否运行了 `启动正式系统.cmd`；8080 端口是否被占用 | 重启正式入口；仍失败时由管理员查看启动错误 |
| 页面显示“网关离线” | `http://127.0.0.1:8080/health` 是否可访问 | 重启正式系统，不要改用演练页面替代现场数据 |
| 设备没有出现 | 边缘适配器是否运行；`deviceId` 是否唯一；上报地址是否为 `8878` | 用第 6 节 PowerShell 报文分离验证平台与适配器问题 |
| 设备状态不刷新 | 适配器上报周期、链路、时间戳和设备心跳 | 由设备工程师检查厂商协议连接；不要在网页手工修改状态 |
| 没有视频 | 视频边缘网关是否已部署和鉴权 | “未配置现场视频流”是安全状态，不要把演练图当作现场视频 |
| 围栏未生效 | 网页围栏与设备侧围栏是否同版本、同坐标系 | 立即停止相关作业，由安全负责人复核后同步 |
| 任务一直“待现场审批” | 审批与边缘执行适配器尚未部署 | 这是当前系统预期；不要尝试用浏览器绕过审批 |

发生急停、失联、碰撞风险、越界风险或人员风险时，以现场急停、人工接管和应急预案为最高优先级，不以网页状态为唯一依据。

## 10. 电子围栏与视频的正式使用条件

### 10.1 电子围栏

网页保存的围栏会进入本机 `data/operator-state.json`，并同步到当前打开的正式页面。它是运行记录和可视化来源，但不是物理安全措施。

每个实际控制适配器必须校验：围栏版本号、坐标系、有效期、禁入边界、限高/限速/水面规则、设备状态和人工审批结果。飞控、船控和机器人安全控制器必须拥有自己的本地失效保护。

### 10.2 视频

真实视频需要独立视频边缘网关，将厂商 RTSP 或私有视频协议转换为经过鉴权的 WebRTC、HLS 或受控 RTSP 流。浏览器不得直接连设备相机，也不得在公网暴露原始视频地址。

## 11. 从“正式集成”升级到“真实控制”前必须完成的工作

当前系统已经可以作为正式的监测、协同感知、告警处置和任务申请平台使用。要让无人设备实际执行航线、航行、导航或动作，必须另行完成：

- 经过认证的 MAVLink、MQTT、ROS 2 或厂商 SDK **边缘执行适配器**。
- 操作者身份认证、角色权限和完整审计日志。
- 不可重放的审批令牌和任务签名。
- 已审核电子围栏向设备安全控制器的版本同步。
- 急停、失联返航/停车、低电量保护、碰撞/避障和人工接管验证。
- 控制器回执、失败回滚和现场应急预案。
- 封闭场地单设备测试、多设备测试和安全负责人签字。

在这些条件完成前，`live` 真实控制请求会被标准网关拒绝。这是安全保护，不是系统故障。

## 12. 需要提供给设备工程师的资料

为了编写实际边缘适配器，请按设备类型提供以下非敏感资料：

1. 设备型号、固件版本和厂商 SDK/协议版本。
2. MAVLink UDP/串口参数，MQTT Topic 规范，ROS 2 话题/服务规范，或厂商 API 文档。
3. 遥测、传感器、告警、任务状态和视频字段说明。
4. 测试环境的网络拓扑、坐标参考系和地图/GIS 数据来源。
5. 低电量、失联、急停、返航/停车和人工接管策略。
6. 现场验收负责人和允许测试的封闭场地范围。

不要提供私钥、密码、Token、设备序列号完整清单、精确公网地址或个人身份资料。此类信息应只在现场的受控配置系统中处理。

## 13. 交付验收清单

- [ ] 首次部署脚本完成，正式页面可打开。
- [ ] `health` 返回 `status: ok` 和 `mode: integration`。
- [ ] 正式页面无设备时不显示样例设备、样例告警或样例视频。
- [ ] 至少一台设备已通过边缘适配器接入并稳定刷新遥测。
- [ ] 至少一条告警可以从设备侧上报到页面。
- [ ] 围栏可创建、保存、删除，并完成设备侧同步验证。
- [ ] 视频流、地图坐标和传感器字段完成现场核对。
- [ ] 单设备失联、急停、低电量和人工接管已验证。
- [ ] 所有真实控制启用前置条件已由安全负责人审批。
